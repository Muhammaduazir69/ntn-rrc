NR-NTN SIB19, timing advance and DRX in ns-3

ns-3 module for the NR-NTN control plane: SIB19 ephemeris a UE decodes, payload-aware timing advance with the feeder leg, K_offset and DRX.

What ntn-rrc does

ntn-rrc is an ns-3 module that adds the NR-NTN control-plane timing mechanisms: a SIB19 (NTN-Config-r17) broadcaster driven by a live orbit, a UE-side uplink timing pre-compensator that decodes it, and a timing advance that includes the feeder leg for transparent payloads. It also provides K_offset derivation, RAR window checks, quantized measurement reports, GNSS location reporting and a connected-mode DRX state machine that gates a real flow.

Accompanying studyValidity of Broadcast Assistance Information for Uplink Timing Pre-Compensation in LEO Non-Terrestrial Networks. Code and data are in this repository.

What it models

NR over a satellite relies on three timing mechanisms that terrestrial ns-3 does not have: a broadcast K_offset that shifts the uplink grant, a timing advance that pre-compensates propagation, and a validity duration after which the terminal must read SIB19 again. ntn-rrc computes the total timing advance as 2(d_service + d_feeder)/c, split into common and UE-specific parts with drift rate and drift variation, so a transparent payload carries the feeder leg. The SIB19 broadcaster fills NTN-Config-r17 from a real orbit (ECEF state vector, ta-Common, drift terms, ul-SyncValidityDuration, K_offset, kMac) and quantizes it to the 3GPP TS 38.331 field steps. It supports a gateway or satellite uplink sync reference point, Taylor, economized or window-fit coefficients, and slot-over-drift, error-budget or fixed validity rules, and derives K_offset = ceil(RTT / slot) + 1 following 3GPP TS 38.213 Section 4.2.

On the UE side, a pre-compensator decodes SIB19, propagates the satellite from the last GNSS fix with a linear, gravity-ECEF, Kepler or Kepler-J2 model and forms its own timing advance. Further classes check whether ra-ResponseWindow can express the RAR window a round trip demands (TS 38.213 Section 8.1, TR 38.821 Section 7.3), quantize MeasurementReport content to TS 38.133 level indices, report GNSS location periodically, on events or on demand, and run connected-mode DRX (TS 38.321) with an extra AwaitingPass state between visibility windows. SIB19 is decoded from a trace and buffer rather than carried on BCCH, and K_offset reaches the scheduler only where the ntn-traffic helper enables it.

Install

Every module ships in the ready-built container image of the toolkit (version 2.7.1):

docker pull uzairdocker69/ns3-ntn-toolkit:latest
docker run --rm -it uzairdocker69/ns3-ntn-toolkit:latest bash

To build from source, clone ns3-ntn-toolkit, which vendors this module under contrib/, or follow the README of this repository (branch ntn-rrc-v2).
